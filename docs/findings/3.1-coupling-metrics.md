# 3.1 Coupling Metrics — Import Graph Analysis

**Requirement traced:** 7.1  
**Methodology:** Parsed all `mod`, `use`, `pub use`, and `crate::` path references across every source file to build a directed import graph. For each module, computed afferent coupling (Ca = how many other modules import from this one), efferent coupling (Ce = how many other modules this one imports from), and instability (I = Ce / (Ca + Ce)). Hotspots flagged where Ca > 3 AND Ce > 3.

## Hotspot Analysis

### Confirmed Hotspot: `src/app` module (Ca=4, Ce=6)

The `app` module is the only module exceeding both Ca > 3 AND Ce > 3:

- **Afferent coupling (Ca=4):** Imported by `main.rs`, `runtime.rs`, `event.rs`, `ui/`
- **Efferent coupling (Ce=6):** Imports from `action`, `audio`, `favorites`, `history`, `radio`, `ui::theme`
- **Instability: 0.60** — moderately unstable; changes here propagate widely

This is architecturally expected for the central application state module, but the high coupling makes it a maintenance risk. Any change to `App`'s public interface cascades to 4 dependent modules.

### Near-Hotspot: `src/radio` module (Ca=6, Ce=0)

- Ca=6 (imported by app, favorites, main, playlist, playlist_export, ui)
- Ce=0 (fully self-contained)
- Instability: 0.00 — maximally stable

Not a hotspot (Ce ≤ 3), but notable as the most depended-upon module. Its stability score (0.00) confirms it should change rarely — any breaking change to `Station` or `station_url_matches` affects 6 modules.

### Near-Hotspot: `src/favorites.rs` (Ca=4, Ce=3)

- Ca=4 (imported by app, cli, main, ui)
- Ce=3 (imports from config, radio, text)
- Instability: 0.43

Just below the hotspot threshold (Ce=3, not > 3). High afferent coupling means changes to `Library`'s interface have wide impact.

## Key Observations for Consolidation

1. **`app` is the single architectural nexus** — it touches 6 dependencies and is consumed by 4 modules. Refactoring `app` requires coordinating across most of the codebase.
2. **`radio` is the most stable dependency** — 6 consumers rely on it, making any breaking change expensive. Its types (`Station`, identity matchers) are effectively the shared domain vocabulary.
3. **`audio` is well-isolated** — zero production imports from other modules (the test-only import of `classify_playback_error` is a minor coupling leak, but not a production concern).
4. **`ui` has high efferent coupling (Ce=4)** but low afferent (Ca=1) — this is correct for a leaf rendering layer. Its instability of 0.80 means it should be easy to change without cascading effects.
5. **Infrastructure modules are appropriately stable** — `config`, `history`, `playlist` have low instability scores, meaning they form reliable foundations.
