| 5 | `src/app/lifecycle.rs` | `handle_audio_error` | 312–314 |


**Proposed abstraction:**
```rust

        self.buffer_percent = 0;

    }
}
```
- **Target module:** `src/app/playback.rs` (on `PlaybackView` impl)

## DRY-PB-03: Dead Audio Engine / Codec Failure Error State Setup

**Pattern:** When the audio command channel is closed or a codec is unsupported, the same 4-step error ceremony is performed: set `state = Error(...)`, set `decoder_state = Failed`, set `last_error = Some(...)`, and call `set_error_notice(...)`.

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/app/playback.rs` | `send_audio_command` | 34–38 |
| 2 | `src/app/playback.rs` | `validate_station_playback_capability` | 85–100 |

**Repeated structure:**
```rust
self.playback.view.state = PlaybackState::Error(/* state message */);
self.playback.diagnostics.decoder_state = DecoderState::Failed;
self.playback.diagnostics.last_error = Some(/* diagnostic detail */);
self.set_error_notice(/* user-visible message */);
```

**Proposed abstraction:**
```rust
impl App {
    fn enter_playback_error(
        &mut self,
        state_message: String,
        diagnostic_detail: String,
        notice: impl Into<String>,
    ) {
        self.playback.view.state = PlaybackState::Error(state_message);
        self.playback.diagnostics.decoder_state = DecoderState::Failed;
        self.playback.diagnostics.last_error = Some(diagnostic_detail);
        self.set_error_notice(notice);
    }
}
```
- **Target module:** `src/app/playback.rs`
- **Variation points:** `state_message`, `diagnostic_detail`, `notice` text.

## DRY-PB-05: Transition to Connecting State

**Pattern:** Set `playback.view.state = PlaybackState::Connecting` as a "starting connection" transition, typically immediately before the play-and-sync-volume sequence.

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/app/playback.rs` | `retry_stream` | 124 |
| 2 | `src/app/lifecycle.rs` | `apply_startup_autoplay` | 160 |
| 3 | `src/app/lifecycle.rs` | `handle_audio_stopped` (reconnect branch) | 296 |
| 4 | `src/app/reconnect.rs` | `drive_reconnect` | 64 |

**Note:** Each site performs the same transition (`state = Connecting`) immediately preceding the play-and-sync sequence (DRY-PB-04). Combining these into the `start_stream` helper would naturally absorb this transition.

**Proposed abstraction:** Fold into `start_stream` above:
```rust
impl App {
    fn start_stream(&mut self, url: String) -> bool {
        self.playback.view.state = PlaybackState::Connecting;
        if self.send_audio_command(AudioCommand::Play(url)) {
            self.sync_volume();
            true
        } else {
            false
        }
    }
}
```
- **Target module:** `src/app/playback.rs`
- **Variation points:** None — all sites set Connecting before playing.

## DRY-PB-06: Reconnect Disarm Within State Reset Context

**Pattern:** Call `reconnect.disarm()` as part of a broader state change — either preparing for a new play attempt or cleaning up after a terminal stop/error.

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/app/playback.rs` | `play_selected` | 54 |
| 2 | `src/app/playback.rs` | `validate_station_playback_capability` | 90 |
| 3 | `src/app/lifecycle.rs` | `handle_audio_stopped` (intentional branch) | 293 |
| 4 | `src/app/lifecycle.rs` | `poll_audio_status` (Playing handler) | 192 |
| 5 | `src/app/reconnect.rs` | `drive_reconnect` (exhausted branch) | 72 |

**Analysis:** Although `disarm()` itself is a single method call, it always appears within a stereotyped sequence: reset transient state → disarm reconnect → transition state. The surrounding ceremony is duplicated each time.

**Proposed abstraction:** Combine with the buffer reset (DRY-PB-01) into a unified "prepare for new playback" helper:
```rust
impl App {
    fn reset_for_playback_attempt(&mut self) {
        self.playback.view.reset_transient_status();
        self.playback.reconnect.disarm();
    }
}
```
- **Target module:** `src/app/playback.rs`
- **Variation points:** Some sites also clear `playing_url`; can be an optional parameter or separate full-stop variant.

## DRY-PB-07: Volume Adjustment Pattern

**Pattern:** `volume_up` and `volume_down` share identical structure: compute progressive step, apply saturating arithmetic, call `sync_volume()`, call `mark_ui_state_dirty()`.

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/app/playback.rs` | `volume_up` | 174–179 |
| 2 | `src/app/playback.rs` | `volume_down` | 182–186 |

**Repeated structure:**
```rust
let step = progressive_volume_step(self.playback.volume);
self.playback.volume = self.playback.volume.saturating_add/sub(step)...;
// (volume_up also sets muted = false)
self.sync_volume();
self.mark_ui_state_dirty();
```

**Proposed abstraction:**
```rust
enum VolumeDirection { Up, Down }

impl App {
    fn adjust_volume(&mut self, direction: VolumeDirection) {
        let step = progressive_volume_step(self.playback.volume);
        match direction {
            VolumeDirection::Up => {
                self.playback.volume = self.playback.volume.saturating_add(step).min(100);
                self.playback.muted = false;
            }
            VolumeDirection::Down => {
                self.playback.volume = self.playback.volume.saturating_sub(step);
            }
        }
        self.sync_volume();
        self.mark_ui_state_dirty();
    }
}
```
- **Target module:** `src/app/playback.rs`
- **Variation points:** Direction (up/down), unmute-on-up behavior.

## DRY-PB-08: Full Stopped-State Reset Sequence

**Pattern:** When playback intentionally stops, a comprehensive reset of view + diagnostics + reconnect is performed. This is a superset of DRY-PB-01 + DRY-PB-02 + DRY-PB-06.

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/app/lifecycle.rs` | `handle_audio_stopped` (intentional branch) | 283–293 |

**Code (11 statements):**
```rust
self.playback.view.intentional_stop = false;
self.playback.view.playing_url = None;
self.playback.view.current_track = None;
self.playback.view.buffer_percent = 0;
self.playback.view.buffer_seconds = 0;
self.playback.view.state = PlaybackState::Stopped;
self.playback.diagnostics.decoder_state = DecoderState::Idle;
self.playback.diagnostics.buffer_percent = 0;
self.playback.diagnostics.buffer_seconds = 0;
self.playback.diagnostics.last_event = Some("Playback stopped".to_string());
self.playback.reconnect.disarm();
```

**Analysis:** Currently a single occurrence, but it establishes the canonical "full stop" that other partial resets approximate. Extracting composable reset methods (`PlaybackView::reset_to_stopped()`, `PlaybackDiagnostics::reset_to_idle()`) allows partial resets to compose from the same building blocks, preventing future drift.

**Proposed abstraction:**
```rust
impl PlaybackView {
    pub fn reset_to_stopped(&mut self) {
        self.intentional_stop = false;
        self.playing_url = None;
        self.current_track = None;
        self.buffer_percent = 0;
        self.buffer_seconds = 0;
        self.state = PlaybackState::Stopped;
    }
}

impl PlaybackDiagnostics {
    pub fn reset_to_idle(&mut self) {
        self.decoder_state = DecoderState::Idle;
        self.buffer_percent = 0;
        self.buffer_seconds = 0;
        self.last_event = Some("Playback stopped".to_string());
    }
}
```
- **Target module:** `src/app/playback.rs` for `PlaybackView`, `src/app/types.rs` for `PlaybackDiagnostics`
