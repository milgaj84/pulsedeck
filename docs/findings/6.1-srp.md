# 6.1 Single Responsibility Principle Violations

_Requirements: 4.1, 4.2, 4.3, 4.4_

## Summary

Analyzed the `App` struct, `UiRuntimeState`, `PlaybackRuntime`, `PlaybackView`, and functions in `src/app/playback.rs` for SRP violations. Found **4 concrete SRP violations** with mixed responsibility fields and **1 module-level violation** where playback state transitions are interleaved with user-facing notice message construction.

---

## SRP-1: `UiRuntimeState` holds audio-engine data

**File:** `src/app/ui_runtime.rs`  
**Severity:** Medium  
**Mixed responsibilities:** ui-rendering + audio-engine + app-state

### Field Classification

| Field | Responsibility |
|-------|---------------|
| `nav: Navigation` | **app-state** |
| `command_palette: CommandPaletteState` | ui-rendering |
| `should_quit: bool` | **app-state** |
| `notice: NoticeState` | ui-rendering |
| `input_mode: InputMode` | ui-rendering |
| `tick_count: u64` | ui-rendering |
| `layout_mode: LayoutMode` | ui-rendering |
| `overlays: Overlays` | ui-rendering |
| `visualizer_mode: usize` | ui-rendering |
| `visualizer_peaks: Vec<f32>` | **audio-engine** |

### Violation Details

1. **`visualizer_peaks: Vec<f32>`** — Raw audio FFT sample data stored in a UI struct. This is audio-engine output that the UI *consumes* for rendering. Storing it here creates an ownership coupling: audio processing code must reach into `App.ui` to push peak data.

2. **`nav: Navigation` and `should_quit: bool`** — These are application state (navigation position, quit signal) that happen to live inside a "UI runtime" struct. Navigation selection affects which station is played, genre-filtered, etc. — it's app behavior, not rendering state.

### Proposed Decomposition

**Split `UiRuntimeState` into:**

```
src/app/ui_runtime.rs     → UiRenderState (pure rendering concerns)
src/app/ui_runtime.rs     → (nav and should_quit move to App top-level or a new AppNav struct)
```

**New `UiRenderState`:**
```rust
pub struct UiRenderState {
    pub command_palette: CommandPaletteState,
    pub notice: NoticeState,
    pub input_mode: InputMode,
    pub tick_count: u64,
    pub layout_mode: LayoutMode,
    pub overlays: Overlays,
    pub visualizer_mode: usize,
}
```

**Fields that move:**
- `nav: Navigation` → `App.nav` (top-level field on `App`)
- `should_quit: bool` → `App.should_quit` (top-level field on `App`)
- `visualizer_peaks: Vec<f32>` → `PlaybackRuntime.visualizer_peaks` (co-locate with other audio data: `sample_buffer`, `volume`, `audio`)

**Public interface change:**
- `App.ui.nav` → `App.nav`
- `App.ui.should_quit` → `App.should_quit`
- `App.ui.visualizer_peaks` → `App.playback.visualizer_peaks`
- `UiModel` references update from `&app.ui.visualizer_peaks` → `&app.playback.visualizer_peaks`

## SRP-2: `PlaybackRuntime` mixes audio-engine, app-state, and infrastructure

**File:** `src/app/playback_runtime.rs`  
**Severity:** Medium  
**Mixed responsibilities:** audio-engine + app-state + infrastructure

### Field Classification

| Field | Responsibility |
|-------|---------------|
| `view: PlaybackView` | app-state (what the UI sees) |
| `volume: u8` | audio-engine |
| `muted: bool` | audio-engine |
| `reconnect: Reconnect` | **infrastructure** (retry/resilience) |
| `diagnostics: PlaybackDiagnostics` | **infrastructure** (debug/observability) |
| `sleep_timer: SleepTimer` | **app-state** (user feature timer) |
| `audio: AudioEngine` | audio-engine |
| `sample_buffer: Arc<Mutex<VecDeque<f32>>>` | audio-engine |

### Violation Details

1. **`sleep_timer: SleepTimer`** — A user-facing feature timer (countdown to stop playback) bundled with audio engine handles. The sleep timer has nothing to do with audio processing; it's a UX feature that happens to *trigger* a stop command. It belongs in app-state.

2. **`reconnect: Reconnect` and `diagnostics: PlaybackDiagnostics`** — Infrastructure-level resilience and observability mechanisms living alongside the audio connection. Reconnect manages backoff/retry policy; diagnostics collect debug info for the "playback doctor" overlay. Both are infrastructure concerns, not core audio-engine state.

3. **Result:** This struct has 3 distinct reasons to change: (a) audio engine API changes, (b) reconnect/diagnostics policy changes, (c) sleep timer behavior changes.

### Proposed Decomposition

**Split `PlaybackRuntime` into:**

```
src/app/playback_runtime.rs → AudioConnection (pure audio-engine interface)
src/app/playback_runtime.rs → PlaybackInfra (resilience + diagnostics)
src/app.rs                  → sleep_timer moves to App top-level
```

**New `AudioConnection`:**
```rust
pub struct AudioConnection {
    pub audio: AudioEngine,
    pub sample_buffer: Arc<Mutex<VecDeque<f32>>>,
    pub volume: u8,
    pub muted: bool,
}

impl AudioConnection {
    pub fn output_volume_fraction(&self) -> f32 { ... }
}
```

**New `PlaybackInfra`:**
```rust
pub struct PlaybackInfra {
    pub reconnect: Reconnect,
    pub diagnostics: PlaybackDiagnostics,
}
```

**Fields that move:**
- `sleep_timer` → `App.sleep_timer` (top-level)
- `view` stays as a peer struct (already named `PlaybackView`)

**Composite in `App`:**
```rust
pub struct App {
    // ...
    pub playback_view: PlaybackView,        // app-state: what UI sees
    pub audio_conn: AudioConnection,        // audio-engine handle
    pub playback_infra: PlaybackInfra,      // infrastructure: reconnect + diagnostics
    pub sleep_timer: SleepTimer,            // app-state: user feature
}
```

## SRP-3: `PlaybackView` contains audio-engine display metrics

**File:** `src/app/playback.rs`  
**Severity:** Low (boundary case)  
**Mixed responsibilities:** app-state + audio-engine metrics

### Field Classification

| Field | Responsibility |
|-------|---------------|
| `state: PlaybackState` | app-state |
| `playing_url: Option<String>` | app-state |
| `current_track: Option<String>` | app-state |
| `buffer_percent: u8` | **audio-engine** (transient metric) |
| `buffer_seconds: u32` | **audio-engine** (transient metric) |
| `intentional_stop: bool` | app-state |

### Violation Details

`buffer_percent` and `buffer_seconds` are transient audio-engine metrics that represent the stream buffer fill state. They are updated by audio status events and consumed only for UI display. Placing them in `PlaybackView` (an app-state struct representing "what the UI should show") creates a soft coupling: audio events write into an app-state struct.

### Proposed Decomposition

This is a minor SRP tension. Two options:

**Option A — Move to diagnostics (minimal change):**
- Move `buffer_percent` and `buffer_seconds` to `PlaybackDiagnostics` (they already exist there too — currently duplicated!)
- `PlaybackView` becomes purely app-state; buffer info is read from diagnostics during UI snapshot construction

**Option B — Introduce BufferStatus sub-struct (cleaner boundary):**
```rust
pub struct BufferStatus {
    pub percent: u8,
    pub seconds: u32,
}
```
- Owned by the audio-engine side (`AudioConnection` or `PlaybackInfra`)
- Read during `UiModel` construction

**Recommended:** Option A — the duplication already signals that `PlaybackDiagnostics` is the canonical home for these values.

## SRP-4: `App` struct leaks infrastructure fields at top level

**File:** `src/app.rs`  
**Severity:** Low  
**Mixed responsibilities:** app-state + infrastructure

### Field Classification

| Field | Responsibility |
|-------|---------------|
| `library: Library` | app-state |
| `search: SearchState` | app-state |
| `history: History` | app-state |
| `song_history: VecDeque<String>` | app-state |
| `undo_history: VecDeque<(Station, usize, String)>` | app-state |
| `ui: UiRuntimeState` | ui-rendering |
| `playback: PlaybackRuntime` | audio-engine |
| `metadata_refresh_pending: bool` | **infrastructure** |
| `metadata_refresh_running: bool` | **infrastructure** |
| `persist: PersistFlags` | **infrastructure** |

### Violation Details

Three infrastructure-concern fields (`metadata_refresh_pending`, `metadata_refresh_running`, `persist`) sit at the top level of the application state. These manage background I/O coordination, not core domain behavior.

### Proposed Decomposition

**Group into an infra sub-struct:**
```rust
pub(super) struct AppInfra {
    pub metadata_refresh_pending: bool,
    pub metadata_refresh_running: bool,
    pub persist: PersistFlags,
}
```

Access becomes `self.infra.metadata_refresh_pending` etc. This is a low-priority cosmetic improvement that makes the `App` struct's top-level fields purely domain-focused.

## SRP-5: Functions in `src/app/playback.rs` mix state transitions with notice formatting

**File:** `src/app/playback.rs`  
**Severity:** Medium  
**Requirement:** 4.2 — module spans two Separation_Boundaries (app-state transitions + presentation)

### Functions Identified

| Function | State Transition Logic | Notice/Presentation Logic |
|----------|----------------------|--------------------------|
| `send_audio_command` | Sets `view.state`, `diagnostics.*` on failure | `self.set_error_notice("Audio engine is not available")` |
| `validate_station_playback_capability` | Sets `view.state = Error(...)`, resets buffer fields, sets `diagnostics.*` | `self.set_error_notice(format!("{} is not playable yet ({})", ...))` with `display_station_codec()` formatting |
| `retry_stream` | Resets `current_track`, buffer fields, sets `state = Connecting` | `self.set_error_notice("No stream to retry")` and `self.set_info_notice("Retrying stream")` |
| `export_library` | Calls `playlist_export::export_library_m3u` | `self.set_info_notice(format!("Library exported to {}", ...))` and `self.set_error_notice(format!("Export failed: {err}"))` |

### Additional notice-mixing in related modules

| File | Function | Notice Construction |
|------|----------|-------------------|
| `src/app/reconnect.rs` | `drive_reconnect` | `self.set_info_notice(format!("Reconnecting ({n}/{max})"))` |
| `src/app/sleep_timer.rs` | `announce_sleep_timer`, `check_sleep_timer` | Multiple conditional notice format strings |
| `src/app/library.rs` | `remove_library_selection`, `undo_remove_library_selection`, `request_metadata_refresh`, `apply_metadata_refresh_response` | 8 distinct notice construction sites |
| `src/app/settings.rs` | `apply_selected_setting`, `cycle_theme_setting` | `format!("Audio output: {}", ...)`, `format!("Theme: {}", ...)`, etc. |
| `src/app/search.rs` | `try_add_search_result_to_library`, search audition | `"Station saved to library"`, `"Auditioning stream..."` |

### Violation Pattern

Every function that performs a state transition also constructs the user-facing notice message inline. This means:
- Changing a notice message requires touching the state transition function
- Changing a state transition may accidentally break notice wording
- Notice text cannot be tested independently of the full state machine
- Internationalization (future) would require touching every state-transition function

### Proposed Decomposition

**Strategy: Extract a `NoticeBuilder` or notice-construction module.**

```
src/app/notices.rs  (new module)
```

```rust
/// Centralized notice message construction.
/// Each function returns the notice text; the caller sets it.
pub(super) fn codec_blocked_notice(codec: &str, reason: &str) -> String {
    format!("{} is not playable yet ({reason})", display_station_codec(codec))
}

pub(super) fn reconnecting_notice(attempt: u8, max: u8) -> String {
    format!("Reconnecting ({attempt}/{max})")
}

pub(super) fn export_success_notice(path: &std::path::Path) -> String {
    format!("Library exported to {}", path.display())
}

pub(super) fn sleep_timer_notice(timer: &SleepTimer) -> String {
    if timer.is_waiting_for_playback() {
        format!("Sleep timer: {} when playback starts", timer.label())
    } else if timer.is_armed() {
        format!("Sleep timer: {}", timer.label())
    } else {
        "Sleep timer off".to_string()
    }
}

// ... etc.
```

**Benefits:**
- State transition functions become pure state manipulations
- Notice messages are testable in isolation (unit test the formatting without constructing a full `App`)
- Future i18n or notice-style changes happen in one place
- `display_station_codec()` helper moves to this module (currently a private fn in `playback.rs`)

**Public interface:** Functions return `String`; callers do `self.set_info_notice(notices::xyz(...))`.
