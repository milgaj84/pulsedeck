### Risk Distribution

- **High risk (4 items):** `expect()` calls in the audio output and stream source modules. These would panic and crash the audio thread if internal invariants are violated (e.g., during device hotplug or concurrent state changes). The `update.rs` test gap is high because it's the central dispatcher for all user actions.
- **Medium risk (5 items):** `unwrap()` calls on theme color accessors in UI rendering, `expect()` on search prefix metadata table completeness, and the untested idle detection FFI.
- **Low risk (23 items):** Intentional fire-and-forget patterns on channel sends (audio pipeline design), best-effort config migration, and non-critical notification delivery.
