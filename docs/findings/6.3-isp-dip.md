## ISP Analysis: Trait Definitions and No-Op Implementations

### Finding: No custom traits defined in the codebase

The PulseDeck codebase defines **zero custom traits**. A comprehensive scan of all `.rs` files under `src/` found no `trait` keyword usage (neither `pub trait`, `pub(crate) trait`, nor private `trait` declarations).

The only trait implementations present are for standard library traits:
- `Default` — implemented for `PlaybackView`, `UiState`, `Overlays`, `SearchState`, `AppDriver`, `History`, `Settings`, `PlaybackOptions`
- `Drop` — implemented for `TerminalRestoreGuard`, `StderrSilencer`

**ISP Assessment:** No ISP violations exist because there are no custom traits that could force implementors to depend on unused methods. The codebase uses a struct + methods design rather than trait-based polymorphism.

**No `unimplemented!()`, `todo!()`, or empty bodies found** anywhere in the codebase.

### Check 3: `pub(crate)` and `pub(super)` types in `src/audio/` — ✅ None leaked to `src/app/`

**`pub(crate)` modules** declared in `src/audio.rs`:
- `pub(crate) mod types` — contains `Generation`, `EngineState`, `EngineEvent`, `EngineError`, `EndReason`, `PrebufferConfig`, `PlaybackOptions`, `StreamFormat`, `DecodedSource`, `ConnectRequest`
- `pub(crate) mod volume` — contains `VolumeRamp`, `clamp_volume()`

**`pub(super)` modules** declared in `src/audio.rs`:
- `pub(super) mod decode` — contains `DecodePipeline`, `run_worker()`
- `pub(super) mod engine_loop_v2` — contains `EngineLoop`
- `pub(super) mod stream_source` — contains stream source abstractions

**`pub(super)` constant** in `src/audio.rs`:
- `pub(super) const HARDWARE_OUTPUT_ERROR_PREFIX: &str`

**Leak check results:** None of these internal types or modules are referenced by any file in `src/app/` (confirmed via grep). The `pub(crate)` visibility on `types` and `volume` modules technically *permits* access from `src/app/`, but no code currently exercises this path.

## Encapsulation Risk (informational)

While no DIP violations currently exist, the `pub(crate) mod types` and `pub(crate) mod volume` declarations in `src/audio.rs` represent an **encapsulation risk**: future code could accidentally bypass the re-export boundary by importing `crate::audio::types::EngineError` or `crate::audio::volume::VolumeRamp` directly.

**Recommendation:** Downgrade these to `pub(super)` (or plain `mod` where possible) to make the compiler enforce the boundary. This is already noted in the 3.2 boundary map findings.
