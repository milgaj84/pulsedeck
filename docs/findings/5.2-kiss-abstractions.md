# 5.2 KISS — Unnecessary Abstractions & Single-Use Conversions

**Audit scope:** Generic type parameters, trait definitions, conversion functions, and wrapper types in `src/`.

**Requirements traced:** 3.3, 3.4

---

## Summary

| Category | Count |
|----------|-------|
| Generic with single concrete instantiation | 1 |
| Single-use conversion (no validation) | 4 |
| Forwarding wrappers (pure pass-through) | 3 |

**Traits:** The codebase defines zero custom traits. No ISP/single-implementor concerns apply.

## Findings

### KISS-ABS-001: `step_choice<T>` — Generic with single concrete instantiation

| Field | Value |
|-------|-------|
| **File** | `src/app/settings.rs` |
| **Function** | `fn step_choice<T: Copy + PartialEq>(choices: &[T], current: T, forward: bool) -> T` |
| **Line** | 186 |
| **Concrete types** | `ThemeName` only (1 call site at line 81) |
| **Evidence** | The function is generic over `T: Copy + PartialEq` but is only ever instantiated with `ThemeName`. A non-generic equivalent already exists in the same file: `step_output_device_preference` performs the identical cycling logic for `String` slices without generics. |
| **Recommendation** | **Inline or monomorphize.** Replace with `fn step_theme(choices: &[ThemeName], current: ThemeName, forward: bool) -> ThemeName`, matching the existing `step_output_device_preference` pattern. If future settings add more `Copy + PartialEq` cycling (e.g., LayoutMode choices), the generic can be reintroduced at that time. |
| **Priority** | Low |

### KISS-ABS-004: `compact_error_summary` — Single-use conversion, no validation

| **Call sites** | 1 (line 426) |

### KISS-ABS-005: `UiRuntimeState::from_ui_state` — Single-use conversion, no validation

| Field | Value |
|-------|-------|
| **File** | `src/app/ui_runtime.rs` |
| **Function** | `pub(super) fn from_ui_state(ui_state: &super::ui_state::UiState) -> Self` |
| **Line** | 17 |
| **Call sites** | 1 production (line 68 in `src/app/lifecycle.rs`) |
| **Evidence** | The function constructs a `UiRuntimeState` with all default values except `layout_mode` and `visualizer_mode`, which are copied from `UiState`. It performs no validation, no clamping, and no invariant enforcement. The struct has no private fields that would benefit from controlled construction. |
| **Recommendation** | **Keep but document intent.** Although technically a single-use conversion, this function serves as a constructor that encapsulates the default initialization pattern. If the struct gains private fields or invariants in the future, this constructor is the right place to enforce them. The recommendation is to leave it in place but mark it with a brief doc-comment explaining it as a construction boundary rather than a pure conversion. This is borderline — not a strong violation. |
| **Priority** | Low (informational) |

### KISS-ABS-006: `Complex::from_real` — Single-use conversion, no validation

| Field | Value |
|-------|-------|
| **File** | `src/app/visualizer/fft.rs` |
| **Function** | `pub(super) fn from_real(re: f32) -> Self` |
| **Line** | 16 |
| **Body** | `Self { re, im: 0.0 }` |
| **Call sites** | 1 (line 54 in `src/app/visualizer/mod.rs`) |
| **Evidence** | A trivial constructor that sets `im` to zero. It's used in a single `.map(Complex::from_real)` call. The `Complex` struct also has `fn new(re: f32, im: f32)` and `fn zero()` constructors. |
| **Recommendation** | **Keep for readability.** While technically single-use, `Complex::from_real` provides clear intent when used in an iterator pipeline (`.map(Complex::from_real)` reads better than `.map(|re| Complex::new(re, 0.0))`). This is idiomatic Rust for named constructors on math types and does not add cognitive overhead. Not a true violation — marking as informational. |
| **Priority** | Low (informational — no action needed) |

## Conclusion

The codebase is generally disciplined about generics and abstractions. The main actionable finding is **KISS-ABS-001** (`step_choice<T>` with single-type usage) and the three pass-through forwarding wrappers (**KISS-ABS-002, 003, 004**) that could be inlined. The remaining items are cosmetic or borderline, with clear rationale for keeping them.

Total actionable items: **4** (Low priority)
Informational items: **3** (no action required)
Not flagged (justified): **1**
