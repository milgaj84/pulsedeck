## Pattern 1: Duplicated Genre Filtering Logic

**Description:** The genre-based station filtering logic is implemented identically in three locations. All three check for `InputMode::Search` short-circuit, resolve the selected genre from `available_genres`, compare against `"All"`, and filter using `resolve_parent_genre(&s.genre).eq_ignore_ascii_case(genre)`.

### Occurrences

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/app/selectors.rs` | `App::visible_stations()` | 10–27 |
| 2 | `src/app/selectors.rs` | `App::visible_count()` | 62–79 |
| 3 | `src/ui/model.rs` | `visible_stations_for()` | 101–125 |

### Shared Logic

```rust
if app.ui.input_mode == InputMode::Search {
    return app.search.results.iter().collect();
}
if let Some(genre) = app.library.available_genres.get(app.ui.nav.selected_genre_idx) {
    if genre == "All" {
        app.library.stations.iter().collect()
    } else {
        app.library.stations.iter()
            .filter(|s| resolve_parent_genre(&s.genre).eq_ignore_ascii_case(genre))
            .collect()
    }
} else {
    app.library.stations.iter().collect()
}
```

### Proposed Abstraction

- **Target module:** `src/favorites.rs` (where `resolve_parent_genre` already lives and `Library` is defined)
- **Signature:**
  ```rust
  pub fn filter_stations_by_genre<'a>(
      stations: &'a [Station],
      available_genres: &[String],
      selected_genre_idx: usize,
  ) -> Vec<&'a Station>
  ```
- **Return type:** `Vec<&'a Station>`
- **Variation points:**
  - The `InputMode::Search` short-circuit is handled *before* calling this helper (caller responsibility)
  - The source collection (`library.stations`) is passed in, so this works for both `App` and `UiModel`

## Pattern 2: Overlay Render Boilerplate (Compact Check → Clear → Block → Content → Alert)

**Description:** Every overlay renderer in `src/ui/` repeats the same 7-step initialization sequence:
1. Compute `popup_area` via `super::centered_rect(W, H, area)`
2. Check if area is compact via a per-module `*_area_is_compact()` function (same logic: `area.width < MIN_W || area.height < MIN_H`)
3. Render `Clear` widget on `popup_area`
4. Call `super::render_boundary_warning()` on compact exit
5. Construct a `Block` with title, `Borders::ALL`, `BorderType::Rounded`, `theme::clear()` background
6. Compute `inner_area` via `block.inner(popup_area)`
7. Call `critical::split_overlay_alert_area(inner_area, &app.player.state)` and conditionally render the alert banner

Only the title string, border color, and content percentages vary.

### Occurrences

| # | File | Function | centered_rect args | Min width/height |
|---|------|----------|--------------------|------------------|
| 1 | `src/ui/help.rs` | `render()` | `(70, 60)` | 60 × 14 |
| 2 | `src/ui/station_details.rs` | `render()` | `(62, 48)` | 56 × 12 |
| 3 | `src/ui/recent_tracks.rs` | `render()` | `(62, 52)` | 56 × 12 |
| 4 | `src/ui/sleep_timer.rs` | `render()` | `(58, 56)` | 56 × 14 |
| 5 | `src/ui/settings.rs` | `render()` | `(54, 64)` | 60 × 18 |
| 6 | `src/ui/playback_doctor.rs` | `render()` | `(72, 72)` | 64 × 18 |
| 7 | `src/ui/command_palette.rs` | `render()` | `(58, 36)` | 52 × 9 |

Each overlay also defines its own `*_area_is_compact(area: Rect) -> bool` function with identical structure:
```rust
fn <name>_area_is_compact(area: Rect) -> bool {
    area.width < MIN_<NAME>_WIDTH || area.height < MIN_<NAME>_HEIGHT
}
```

### Proposed Abstraction

- **Target module:** `src/ui/mod.rs` (extend existing overlay utilities)
- **Signature:**
  ```rust
  pub struct OverlayConfig {
      pub title: &'static str,
      pub percent_x: u16,
      pub percent_y: u16,
      pub min_width: u16,
      pub min_height: u16,
      pub border_color: Color,
      pub compact_label: &'static str,
  }

  /// Returns `Some(inner_area, alert_area)` if the overlay fits,
  /// or `None` after rendering a boundary warning.
  pub fn render_overlay_chrome(
      frame: &mut Frame,
      area: Rect,
      config: &OverlayConfig,
      playback_state: &PlaybackState,
  ) -> Option<(Rect, Option<Rect>)>
  ```
- **Return type:** `Option<(Rect, Option<Rect>)>` — content area + optional alert area
- **Variation points:** title, percentages, min dimensions, border color, compact label text. Content rendering remains caller-specific.

## Pattern 3: Codec Display Formatting (Normalize + Capability Check)

**Description:** Three locations independently normalize the station codec string (trim → empty check → uppercase) and two of the three also call `crate::audio::codec_capability()` to determine playback support. The display format differs slightly but the normalization and capability lookup are repeated.

### Occurrences

| # | File | Function | Logic |
|---|------|----------|-------|
| 1 | `src/app/playback.rs` | `display_station_codec()` (line 246) | `trim → is_empty → "Unknown codec"` / `to_ascii_uppercase` |
| 2 | `src/ui/stations.rs` | `codec_chip()` (line 273) | `trim → is_empty → "codec ?"` / `codec_capability` match → uppercase + suffix |
| 3 | `src/ui/station_details.rs` | `codec_detail()` (line 173) | `fallback` for empty / `codec_capability` match → uppercase + prose description |

All share:
- Trim whitespace from `station.codec`
- Check for empty (different fallback labels)
- Convert to ASCII uppercase
- Two of three additionally call `codec_capability()` and branch on the result

### Proposed Abstraction

- **Target module:** `src/audio/capability.rs` (where `codec_capability` already lives)
- **Signature:**
  ```rust
  pub struct CodecDisplayInfo {
      pub label: String,           // Uppercase codec name or fallback
      pub capability: PlaybackCapability,
      pub reason: &'static str,
  }

  pub fn codec_display_info(codec: &str) -> CodecDisplayInfo
  ```
- **Return type:** `CodecDisplayInfo`
- **Variation points:** Each call site formats the `CodecDisplayInfo` differently (chip suffix, prose description, error notice). The abstraction consolidates the normalize + capability lookup; formatting remains caller-specific.

## Pattern 4: Station Health Timestamp Comparison

**Description:** Both `src/ui/stations.rs` and `src/ui/station_details.rs` implement logic to determine whether a station's last failure timestamp is more recent than its last success timestamp. Both parse `Option<&str>` timestamps as `u64` and compare them, with a string fallback for non-numeric timestamps.

### Occurrences

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/ui/stations.rs` | `station_health_failure_is_current()` | 246–255 |
| 2 | `src/ui/station_details.rs` | `failure_is_after_success()` | 254–259 |

### Shared Logic

`stations.rs`:
```rust
fn station_health_failure_is_current(success: Option<&str>, failure: Option<&str>) -> bool {
    match (success, failure) {
        (_, None) => false,
        (None, Some(_)) => true,
        (Some(success), Some(failure)) => match (success.parse::<u64>(), failure.parse::<u64>()) {
            (Ok(s), Ok(f)) => f > s,
            _ => failure > success,
        },
    }
}
```

`station_details.rs`:
```rust
fn failure_is_after_success(success: &str, failure: &str) -> bool {
    match (success.parse::<u64>(), failure.parse::<u64>()) {
        (Ok(success), Ok(failure)) => failure > success,
        _ => failure > success,
    }
}
```

These implement the same semantic (is failure timestamp newer than success?) with slightly different Option handling.

### Proposed Abstraction

- **Target module:** `src/radio/station.rs` (on `StationHealth` as a method)
- **Signature:**
  ```rust
  impl StationHealth {
      /// Returns `true` when the most recent event is a failure.
      pub fn has_current_failure(&self) -> bool
  }
  ```
- **Return type:** `bool`
- **Variation points:** None — both sites need the same boolean answer. The abstraction encapsulates the timestamp parsing and comparison logic on the domain type where the data lives.

## Pattern 5: Bitrate Formatting (zero-as-unknown, `{bitrate}k`)

**Description:** Two UI files implement nearly identical bitrate-to-string formatting. Both check for `bitrate == 0` and return a fallback, otherwise format as `"{bitrate}k"`. The only difference is the zero-case label (`"?k"` vs `"Unknown"`).

### Occurrences

| # | File | Function | Zero fallback |
|---|------|----------|---------------|
| 1 | `src/ui/stations.rs` | `bitrate_chip()` (line 265) | `"?k"` |
| 2 | `src/ui/station_details.rs` | `bitrate_label()` (line 268) | `"Unknown"` |

### Shared Logic

```rust
fn bitrate_chip(bitrate: u32) -> String {
    if bitrate == 0 { "?k".to_string() } else { format!("{bitrate}k") }
}
fn bitrate_label(bitrate: u32) -> String {
    if bitrate == 0 { "Unknown".to_string() } else { format!("{bitrate}k") }
}
```

### Proposed Abstraction

- **Target module:** `src/radio/station.rs` (domain formatting for `Station` data)
- **Signature:**
  ```rust
  pub fn format_bitrate(bitrate: u32, zero_fallback: &str) -> String
  ```
- **Return type:** `String`
- **Variation points:** `zero_fallback` — the label to use when bitrate is 0. This covers both the compact chip style (`"?k"`) and the verbose detail style (`"Unknown"`).

## Pattern 6: Empty-String Fallback Helper

**Description:** Two UI files define functionally identical helpers that return a fallback `&str` when the input is blank (after trimming).

### Occurrences

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/ui/stations.rs` | `empty_fallback()` | 343–348 |
| 2 | `src/ui/station_details.rs` | `fallback()` | 276–281 |

### Shared Logic

```rust
fn empty_fallback<'a>(value: &'a str, fallback: &'a str) -> &'a str {
    if value.trim().is_empty() { fallback } else { value }
}
// station_details.rs additionally trims the returned value
fn fallback<'a>(value: &'a str, fallback: &'a str) -> &'a str {
    if value.trim().is_empty() { fallback } else { value.trim() }
}
```

### Proposed Abstraction

- **Target module:** `src/text.rs` (cross-cutting text utilities already exist here)
- **Signature:**
  ```rust
  pub fn str_or_fallback<'a>(value: &'a str, fallback: &'a str) -> &'a str
  ```
- **Return type:** `&'a str`
- **Variation points:** Whether to trim the non-empty return value. Can unify by always trimming (current `fallback()` behavior) — callers that pass pre-trimmed values are unaffected.

## Pattern 7: URL Normalization Used for Station Identity Matching

**Description:** `station_url_matches()` is used in 13+ call sites across 4 source files (`src/app/selectors.rs`, `src/app/library.rs`, `src/app/lifecycle.rs`, `src/favorites.rs`). While the function itself is properly centralized in `src/radio/station.rs`, the *usage pattern* — finding a station by URL in a collection — is repeated identically:

```rust
collection.iter().find(|s| station_url_matches(&s.url, target_url))
// or
collection.iter().position(|s| station_url_matches(&s.url, target_url))
```

| 5 | `src/app/library.rs` | `App::undo_remove_station()` | 78 |
| 6 | `src/app/library.rs` | `App::select_after_remove()` | 210 |
| 7 | `src/app/lifecycle.rs` | `autoplay_index()` | 13 |
| 8 | `src/app/lifecycle.rs` | `App::handle_status()` | 148 |
| 9 | `src/app/lifecycle.rs` | `App::handle_status()` | 241 |

### Proposed Abstraction

- **Target module:** `src/radio/station.rs` (extend existing URL utilities)
- **Signature:**
  ```rust
  pub fn find_station_by_url<'a>(stations: &'a [Station], url: &str) -> Option<&'a Station>
  ```

- **Return type:** `Option<&Station>` / `Option<usize>`
- **Variation points:** Some callers use `find` (get reference), others use `position` (get index). Two helpers cover both cases. Callers searching `Vec<&Station>` (visible lists) would still use inline `.position()` but the more common `&[Station]` case is consolidated.
