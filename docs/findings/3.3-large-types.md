### Key SRP Concerns (Req 4.4)

1. **`PlaybackRuntime`** straddles audio-engine and app-state; `PlaybackView` within it mixes app-state with UI display hints.
2. **`PlaybackDiagnostics`** spans 4 responsibility boundaries — it's a diagnostics view-model rather than a focused single-responsibility struct.
3. **`UiRuntimeState`** is mostly clean (UI rendering) but holds `visualizer_peaks` (audio data) and `should_quit` (app lifecycle).
4. **`App`** acceptably spans boundaries as the composition root, with proper delegation to `ui` and `playback` sub-structs.
5. **`UiModel`** is large (22 fields) but is a read-only snapshot struct, so its size is architecturally appropriate — it's the "projection" from `App` to the UI layer.
