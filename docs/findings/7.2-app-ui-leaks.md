# 7.2 Audit: App-State Functions for UI Construction Leaks

**Requirements traced:** 6.2, 6.6

**Boundary rule:** App-state (`src/app/`) should NEVER construct ratatui widgets or perform raw filesystem/IO operations directly.

---

## Summary

| Category | Violations Found |
|----------|-----------------|
| Ratatui widget construction | 0 |
| Direct filesystem I/O | 2 (in 1 file) |
| Direct process spawn (I/O) | 1 (in same file) |
| **Total boundary violations** | **3** |

All violations are located in `src/app/notifier.rs`, which performs desktop notification dispatch including a WSL detection path that reads from the filesystem and a Windows balloon notification fallback that spawns a subprocess.

---

## Ratatui Widget Construction Scan

**Types searched:** `Span`, `Line`, `Style`, `Layout`, `Rect`, `Constraint`, `Color`, `Widget`, `Frame`, `Block`, `Borders`

**Result:** ✅ No violations found.

No ratatui imports (`use ratatui::*`) exist anywhere in `src/app/` or `src/app.rs`. The `LayoutMode` enum referenced in `ui_state.rs` and `ui_runtime.rs` is a domain-level enum defined in `src/app/types.rs` — not a ratatui type.

## Direct Filesystem I/O Scan

**Patterns searched:** `std::fs::*`, `std::io::*`, `File::`, `fs::read`, `fs::write`, `fs::create_dir`, `OpenOptions`, `BufReader`, `BufWriter`, `Command::new`

### Violation 1: `std::fs::read_to_string` in `notifier.rs`

| Field | Value |
|-------|-------|
| **File** | `src/app/notifier.rs` |
| **Function** | `is_wsl()` |
| **Line** | 21 |
| **Type used** | `std::fs::read_to_string` |
| **Context** | Reads `/proc/sys/kernel/osrelease` to detect WSL environment |

```rust
fn is_wsl() -> bool {
    std::fs::read_to_string("/proc/sys/kernel/osrelease")
        .map(|release| is_wsl_osrelease(&release))
        .unwrap_or(false)
}
```

**Violation rationale:** Direct filesystem read in app-state layer. This platform detection should be delegated to an infrastructure/platform module.

### Violation 3: `std::process::Command` spawn in `notifier.rs`

| Field | Value |
|-------|-------|
| **File** | `src/app/notifier.rs` |
| **Function** | `spawn_windows_balloon()` |
| **Line** | 33 |
| **Type used** | `std::process::Command` (via `Command::new`) |
| **Context** | Spawns `powershell.exe` to display a Windows balloon notification |

```rust
fn spawn_windows_balloon(summary: &str, body: &str) -> std::io::Result<()> {
    let script = windows_balloon_script(summary, body);
    Command::new("powershell.exe")
        .arg("-NoProfile")
        ...
        .spawn()
        .map(|_| ())
}
```

**Violation rationale:** Direct process spawning in app-state layer. This system interaction should be encapsulated in an infrastructure/platform module.

## Recommendation

Extract `src/app/notifier.rs` into an infrastructure module (e.g., `src/notification.rs` or `src/platform.rs`) that encapsulates:
1. WSL detection (`is_wsl` + filesystem read)
2. Windows balloon notification dispatch (`spawn_windows_balloon` + process spawn)
3. The `notify-rust` native notification call

The app-state layer would then call a single `notify_now_playing(title, station)` function exposed by the infrastructure module, keeping I/O out of the `src/app/` boundary entirely.
