## Encapsulation Risks — `pub` Fields Without Public Constructor/Builder

These structs expose all fields as `pub` and rely on either `#[derive(Default)]` or direct struct literal construction, meaning external code can freely construct or mutate them without enforcing invariants. Structs that are purely data-carrying (DTOs) with no invariants are noted but still flagged per the acceptance criteria.

| # | Struct | File | Line | Field Count | Has `new()`/Builder | Risk |
|---|--------|------|------|-------------|---------------------|------|
| 1 | `PlaybackView` | `src/app/playback.rs` | 4 | 6 pub fields | No (`Default` only) | encapsulation-risk |
| 2 | `PlaybackDiagnostics` | `src/app/types.rs` | 55 | 10 pub fields | No (`Default` only) | encapsulation-risk |
| 3 | `Navigation` | `src/app/nav.rs` | 4 | 5 pub fields | No (`Default` only) | encapsulation-risk |
| 4 | `Overlays` | `src/app/overlays.rs` | 17 | 2 pub fields | No (`Default` only) | encapsulation-risk |
| 5 | `UiRuntimeState` | `src/app/ui_runtime.rs` | 4 | 10 pub fields | `pub(super) from_ui_state()` only | encapsulation-risk |
| 6 | `CommandPaletteState` | `src/app/command_palette.rs` | 6 | 2 pub fields | No (`Default` only) | encapsulation-risk |
| 7 | `SearchState` | `src/app/search.rs` | 5 | 6 pub fields | No (`Default` only) | encapsulation-risk |
| 8 | `PlaybackRuntime` | `src/app/playback_runtime.rs` | 5 | 8 pub fields | `pub(super) new()` only | encapsulation-risk |

### Notes

- **`PlaybackRuntime`** has a `pub(super) fn new(...)` constructor, but all 8 fields are `pub`, meaning any code within the `app` module (and via `App`'s pub field `app.playback`) can bypass the constructor and mutate fields directly. External crate users can mutate `app.playback.volume` etc. without validation.
- **`UiRuntimeState`** similarly has a `pub(super)` factory (`from_ui_state`) but all fields are `pub`. Since `App.ui` is `pub`, external code can freely mutate all UI runtime state.
- **`PlaybackDiagnostics`** has 10 `pub` fields (borderline large type) and no invariant enforcement. It is essentially a telemetry bag, but `buffer_percent` (0–100 range) and `reconnect_attempts` (0–limit) have implicit constraints that are not enforced by type or constructor.
- **`ThemePalette`** (`src/ui/theme/palette.rs` line 10) has 13 `pub` fields and no public constructor. However, all construction is via `pub(super)` palette functions (e.g., `palette_retrowave()`), and the struct is `pub use`-exported. External callers can construct arbitrary palettes. This is intentional for extensibility but noted.
- **`HistoryEntry`** (`src/history.rs` line 10) has 3 `pub` fields with no constructor — it's a serialization DTO. Low risk.
- **`RankExplanation`** (`src/radio/rank.rs` line 8) has 1 `pub` field (`signals: Vec<RankSignal>`) with no constructor. Low risk (read-only analysis result).

### Excluded (have proper constructors/encapsulation)

- `App` — has `pub fn new(library)` and private fields `metadata_refresh_pending`, `persist`
- `Library` — has `pub fn load(...)`, `pub fn load_existing()`
- `Station` — has `pub fn basic(...)` constructor
- `SleepTimer` — all fields are private, accessed via methods
- `Reconnect` — all fields are private, accessed via methods
- `NoticeState` — mixed: `pub current` but `ticks_remaining` is private (partially encapsulated)
- `AudioEngine` — has `pub fn spawn(...)`, only `status_rx` is pub

### Analysis

All `Arc<Mutex<VecDeque<f32>>>` (the shared `sample_buffer`) lock sites are in synchronous code:

| Lock Site | File | Line | Context |
|-----------|------|------|---------|
| `self.playback.sample_buffer.lock()` | `src/app/visualizer/mod.rs` | 27 | Synchronous `update_visualizer()` on UI tick |
| `app.sample_buffer.lock()` | `src/ui/deck/visualizer/mod.rs` | 61 | Synchronous UI rendering |
| `self.sample_buffer.try_lock()` | `src/audio/visualizer.rs` | 44 | Synchronous `Iterator::next()` on audio thread |
| `NATIVE_AUDIO_STDERR_LOCK.lock()` | `src/audio/output.rs` | 115 | Synchronous stderr suppression |

The codebase uses `tokio::spawn(async move { ... })` in `src/runtime.rs` for search and metadata refresh, but none of these async tasks touch the `sample_buffer` Mutex. The async code only accesses HTTP client calls (network I/O) — no shared Mutex is held across `.await`.

No `Arc<RwLock<_>>` instances exist in the codebase (the `RwLock<Option<ThemePalette>>` in `src/ui/theme/mod.rs` is a `static`, not wrapped in `Arc`, and is only accessed in synchronous rendering code).

## Concurrency Risks — Nested Lock Acquisitions

| # | File | Line | Pattern | Risk Classification |
|---|------|------|---------|---------------------|
| — | None found | — | — | — |

### Analysis

The codebase uses only two distinct `Mutex` instances in production paths:

1. **`sample_buffer: Arc<Mutex<VecDeque<f32>>>`** — shared between the audio thread (writer via `VisualizerSource::capture_visualizer_sample`) and the UI thread (reader via `update_visualizer` / render).
2. **`NATIVE_AUDIO_STDERR_LOCK: Mutex<()>`** — static lock used only in `with_suppressed_native_audio_stderr` on the audio thread (unix only).

These two locks are never held simultaneously:
- `NATIVE_AUDIO_STDERR_LOCK` is acquired only during device enumeration/open (`list_output_device_names`, `open_output_stream`).
- `sample_buffer` is acquired during audio decode iteration (`try_lock`) and UI tick/render (`lock`).
- No code path acquires both in the same scope.

## Conclusion

The codebase has **no held-across-await** or **nested-lock** concurrency risks. The primary audit finding is the **8 structs with fully-public fields and no enforcing constructor**, which creates encapsulation risks where invariants (e.g., `buffer_percent ∈ [0, 100]`, `volume ∈ [0, 100]`, `reconnect_attempts ≤ limit`) are not type-enforced and can be violated by any code with access to the struct.
