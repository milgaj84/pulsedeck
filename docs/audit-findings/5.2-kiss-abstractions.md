## KISS-ABS-01: `step_choice<T>` — Generic with Single Concrete Instantiation

**File:** `src/app/settings.rs`  
**Line:** 186  
**Requirement:** 3.3

```rust
fn step_choice<T: Copy + PartialEq>(choices: &[T], current: T, forward: bool) -> T
```

**Analysis:** The generic type parameter `T: Copy + PartialEq` is only ever instantiated with `ThemeName` (line 81, same file). No other call site exists in the codebase.

**Call sites (1):**

| # | File | Line | Concrete Type |
|---|------|------|---------------|
| 1 | `src/app/settings.rs` | 81 | `ThemeName` |

**Recommendation:** Replace the generic with the concrete type `ThemeName` directly. If future settings need cycling through different types, the generic can be reintroduced then. The function is private to the module, so no public API change is needed.

```rust
fn step_choice(choices: &[ThemeName], current: ThemeName, forward: bool) -> ThemeName
```

**Severity:** Low — the generic adds no harm beyond a minor readability cost, but it contradicts KISS by introducing generality that isn't used.

## KISS-ABS-02: `output_device_names_from_iter<I>` — Generic Iterator with Single Caller

**File:** `src/audio/output.rs`  
**Line:** 96  
**Requirement:** 3.3

```rust
fn output_device_names_from_iter<I>(names: I) -> Vec<String>
where
    I: IntoIterator<Item = String>,
```

**Analysis:** In production code, this function is called exactly once from `list_output_device_names_inner()` (line 35) with a `Filter<Map<...>>` iterator from cpal. The test (line 221) calls it with `Vec<String>`, but that's an artifact of having a testable function — the generic was introduced primarily to enable testing with a `Vec`.

**Call sites (production: 1, test: 1):**

| # | File | Line | Context |
|---|------|------|---------|
| 1 | `src/audio/output.rs` | 35 | Production — `devices.filter_map(...)` |
| 2 | `src/audio/output.rs` | 222 | Test — `vec![...]` |

**Recommendation:** The generic is marginally justified here because it enables a useful unit test without needing a real audio device. However, an alternative design would accept `impl IntoIterator<Item = String>` inline (which is syntactically the same) or simply accept `Vec<String>` and have the caller collect before passing. No change strictly required, but worth noting as borderline over-abstraction.

**Severity:** Low — the generic enables testability, which partly justifies its existence. Flag for awareness rather than immediate action.

## KISS-ABS-03: `VisualizerSource<S>` — Generic Wrapper with Single Concrete Use

**File:** `src/audio/visualizer.rs`  
**Lines:** 16–88  
**Requirement:** 3.3

```rust
pub(super) struct VisualizerSource<S>
where
    S: RodioSource,
    S::Item: RodioSample + CpalSample<Float = f32> + Copy,
```

**Analysis:** `VisualizerSource` is instantiated at exactly one site in `src/audio/decode.rs` (lines 56–57 and 78–79), always wrapping `decoder.convert_samples::<f32>()`. The concrete type is always `rodio::source::SamplesConverter<Decoder<BufReader<ReadWrapper<R>>>, f32>`.

The generic is idiomatic Rust for source adapters in the rodio ecosystem (similar to `rodio::source::Amplify<S>`, `rodio::source::Speed<S>`). Removing it would require boxing the inner source or using a type alias, which could hurt performance in the audio hot path.

**Recommendation:** Retain as-is. While technically single-instantiation, this follows the rodio adapter pattern and the generic enables zero-cost abstraction (no dynamic dispatch in the audio pipeline). Flagged for documentation purposes only.

**Severity:** None (informational) — justified by performance requirements of the audio pipeline.

## KISS-ABS-04: `normalize_country_code` — Trivial Single-Use Conversion

**File:** `src/radio/station.rs`  
**Line:** 188  
**Requirement:** 3.4

```rust
pub fn normalize_country_code(value: &str) -> String {
    value.trim().to_ascii_uppercase()
}
```

**Analysis:** This function performs `trim().to_ascii_uppercase()` — a single chained method call. It is only called from one production site in `src/favorites.rs` (line 86). It does not enforce any validation or domain invariant beyond trimming/casing. The function is `pub` and re-exported through `src/radio.rs`, adding public API surface for a trivial operation.

**Call sites (1):**

| # | File | Line | Context |
|---|------|------|---------|
| 1 | `src/favorites.rs` | 86 | `normalize_country_code(&station.country_code)` |

**Recommendation:** Inline at the call site as `station.country_code.trim().to_ascii_uppercase()`, or consolidate into the `normalize_loaded_station` function that already exists in `favorites.rs`. Remove the public re-export from `src/radio.rs`.

**Severity:** Low — trivial function that adds API surface without providing validation or invariant enforcement.

## KISS-ABS-05: `normalize_station_uuid` — Trivial Single-Use Conversion

**File:** `src/radio/station.rs`  
**Line:** 183  
**Requirement:** 3.4

```rust
pub fn normalize_station_uuid(value: String) -> Option<String> {
    let trimmed = value.trim().to_string();
    (!trimmed.is_empty()).then_some(trimmed)
}
```

**Analysis:** Trims a string and converts empty to `None`. Only called from `src/favorites.rs` (line 85) inside `normalize_loaded_station`. Does not validate UUID format, length, or any domain rule — it's purely a trim-and-empty-check. The identical logic exists as `non_empty()` in `src/radio/map.rs` (line 78), indicating this was possibly extracted prematurely without consolidation.

**Call sites (1):**

| # | File | Line | Context |
|---|------|------|---------|
| 1 | `src/favorites.rs` | 85 | `station.station_uuid.and_then(normalize_station_uuid)` |

**Recommendation:** Inline at the call site, or consolidate with `non_empty()` in `src/radio/map.rs` which has identical semantics. If kept, consider adding actual UUID format validation to justify the abstraction's existence.

**Severity:** Low — the function name implies UUID-specific normalization, but the implementation is generic string trimming.

**File:** `src/radio/map.rs`  
**Line:** 78  
**Requirement:** 3.4

```rust
fn non_empty(value: String) -> Option<String> {
    let trimmed = value.trim().to_string();
    (!trimmed.is_empty()).then_some(trimmed)
}
```

**Analysis:** Identical logic to `normalize_station_uuid` above. Called once (line 53) within `map_api_station`. This is a private helper with a single call site performing trim + empty-to-None conversion. No validation or invariant enforcement.

**Call sites (1):**

| # | File | Line | Context |

**Severity:** Low — private function, but contributes to unnecessary indirection.

## KISS-ABS-07: `fallback_trimmed` — Trivial Single-Use Conversion

**File:** `src/radio/map.rs`  
**Line:** 83  
**Requirement:** 3.4

```rust
fn fallback_trimmed(value: String, fallback: &str) -> String {
    let trimmed = value.trim();
    if trimmed.is_empty() {
        fallback.to_string()
    } else {
        trimmed.to_string()
    }
}
```

**Analysis:** Called exactly once (line 48) in `map_api_station` for the station name. A trivial trim-or-use-fallback that doesn't validate anything. The logic is straightforward enough to inline.

**Call sites (1):**

| # | File | Line | Context |
|---|------|------|---------|
| 1 | `src/radio/map.rs` | 48 | `name: fallback_trimmed(api.name, "Unnamed station")` |

**Recommendation:** Inline at call site. The two-line conditional is clearer in context than a function call to `fallback_trimmed`.

**Severity:** Low — private helper with minimal abstraction value.

## KISS-ABS-08: `normalize_playback_codec` — Single-Use Internal Conversion

**File:** `src/audio/capability.rs`  
**Line:** 94  
**Requirement:** 3.4

```rust
fn normalize_playback_codec(codec: &str) -> String {
    codec
        .trim()
        .to_ascii_uppercase()
        .replace('_', "-")
        .replace(' ', "")

```

**Analysis:** Called from exactly one site — `codec_capability()` (line 32). Unlike `normalize_country_code`, this performs slightly more transformation (underscore replacement, space removal) beyond just trim+uppercase. However, it's still a single-use helper that could be inlined directly into the match expression of `codec_capability`.

**Call sites (1):**

| # | File | Line | Context |
|---|------|------|---------|
| 1 | `src/audio/capability.rs` | 32 | `match normalize_playback_codec(codec).as_str()` |

**Recommendation:** Borderline. The chain of transformations is slightly complex enough that naming it aids readability. Retain if the team prefers named steps; otherwise inline. No urgency.

**Severity:** Low (informational) — marginally justified by readability of the named step.
