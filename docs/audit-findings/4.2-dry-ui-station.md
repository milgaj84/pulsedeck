# 4.2 DRY Violations — UI Rendering & Station Logic

**Requirements:** 2.1, 2.3, 2.5

## Pattern 1: Duplicated Genre Filtering Logic

**Description:** The genre-based station filtering logic is implemented identically in three places — `App::visible_stations()`, `App::visible_count()`, and `visible_stations_for()` in the UI model. All three check for `InputMode::Search` short-circuit, resolve the selected genre from `available_genres`, compare against `"All"`, and filter using `resolve_parent_genre(...).eq_ignore_ascii_case(genre)`.

### Occurrences

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/app/selectors.rs` | `App::visible_stations()` | 8–29 |
| 2 | `src/app/selectors.rs` | `App::visible_count()` | 62–80 |
| 3 | `src/ui/model.rs` | `visible_stations_for()` | 100–124 |

### Evidence

`src/app/selectors.rs` — `visible_stations()`:
```rust
if self.ui.input_mode == InputMode::Search {
    return self.search.results.iter().collect();
}
if let Some(genre) = self.library.available_genres.get(self.ui.nav.selected_genre_idx) {
    if genre == "All" {
        self.library.stations.iter().collect()
    } else {
        self.library.stations.iter()
            .filter(|s| resolve_parent_genre(&s.genre).eq_ignore_ascii_case(genre))
            .collect()
    }
} else {
    self.library.stations.iter().collect()
}
```

`src/ui/model.rs` — `visible_stations_for()`:
```rust
if app.ui.input_mode == InputMode::Search {
    return app.search.results.iter().collect();
}
if let Some(genre) = app.library.available_genres.get(app.ui.nav.selected_genre_idx) {
    if genre == "All" {
        app.library.stations.iter().collect()
    } else {
        app.library.stations.iter()
            .filter(|station| resolve_parent_genre(&station.genre).eq_ignore_ascii_case(genre))
            .collect()
    }
} else {
    app.library.stations.iter().collect()
}
```

### Proposed Abstraction

- **Target module:** `src/app/selectors.rs` (keep `App::visible_stations()` as the single implementation)
- **Signature:** Already exists as `pub fn visible_stations(&self) -> Vec<&Station>`
- **Resolution:** Remove `visible_stations_for()` from `src/ui/model.rs` and call `app.visible_stations()` directly in `UiModel::from()`. The `visible_count()` method could be derived from `visible_stations().len()` or kept as a zero-alloc optimization.
- **Variation points:** None — the logic is byte-for-byte identical in control flow.

## Pattern 2: Overlay Render Boilerplate (Compact Check → Clear → Block → Content → Alert)

**Description:** Every overlay renderer in `src/ui/` repeats the same 7-step initialization sequence: (1) compute `popup_area` via `centered_rect(W, H, area)`, (2) check if area is compact via a per-module `*_area_is_compact()` function, (3) render `Clear` widget, (4) call `render_boundary_warning`, (5) construct a `Block` with identical border styling, (6) split content area via `critical::split_overlay_alert_area`, (7) render `block` then content then optional alert banner. The only variation points are the title string, width/height percentages, and minimum dimension constants.

### Occurrences

| # | File | Function | Width% | Height% | MinW | MinH |
|---|------|----------|--------|---------|------|------|
| 1 | `src/ui/help.rs` | `render()` | 70 | 60 | 60 | 14 |
| 2 | `src/ui/station_details.rs` | `render()` | 62 | 48 | 56 | 14 |
| 3 | `src/ui/recent_tracks.rs` | `render()` | 62 | 52 | 56 | 12 |
| 4 | `src/ui/sleep_timer.rs` | `render()` | 58 | 56 | 56 | 14 |
| 5 | `src/ui/settings.rs` | `render()` | 54 | 64 | 60 | 18 |
| 6 | `src/ui/playback_doctor.rs` | `render()` | 72 | 72 | 64 | 18 |
| 7 | `src/ui/command_palette.rs` | `render()` | 58 | 36 | 42 | 10 |

### Evidence (representative: sleep_timer.rs)

```rust
let popup_area = super::centered_rect(58, 56, area);
if sleep_area_is_compact(popup_area) {
    frame.render_widget(Clear, popup_area);
    super::render_boundary_warning(frame, popup_area, "Sleep Timer Too Compact", format!(...));
    return;
}
frame.render_widget(Clear, popup_area);
let block = Block::default()
    .title(Span::styled(" 💤 Sleep Timer 💤 ", theme::title()))
    .borders(Borders::ALL)
    .border_style(Style::default().fg(theme::accent_secondary()).add_modifier(Modifier::BOLD))
    .border_type(ratatui::widgets::BorderType::Rounded)
    .style(theme::clear());
let inner_area = block.inner(popup_area);
let (content_area, alert_area) = critical::split_overlay_alert_area(inner_area, &app.player.state);
frame.render_widget(block, popup_area);
// ... render content ...
if let Some(alert_area) = alert_area {
    critical::render_engine_fault_banner(frame, alert_area, &app.player.state);
}
```

Each `*_area_is_compact` function is also duplicated — they all have the pattern `area.width < MIN_X || area.height < MIN_Y`.

### Proposed Abstraction

- **Target module:** `src/ui/mod.rs` (extend existing overlay utilities)
- **Signature:**
  ```rust
  pub struct OverlayConfig {
      pub title: &'static str,
      pub compact_label: &'static str,
      pub width_percent: u16,
      pub height_percent: u16,
      pub min_width: u16,
      pub min_height: u16,
      pub border_color: Color,  // defaults to accent_secondary()
  }

  /// Returns `Some(inner_area, alert_area)` if the overlay fits, or `None` after rendering
  /// the compact warning in-place.
  pub fn prepare_overlay(
      frame: &mut Frame,
      area: Rect,
      config: &OverlayConfig,
      playback_state: &PlaybackState,
  ) -> Option<(Rect, Option<Rect>)>
  ```
- **Variation points:** `title`, `compact_label`, `width_percent`, `height_percent`, `min_width`, `min_height`, `border_color` (most use `accent_secondary()`, playback_doctor uses `highlight()`).

## Pattern 3: Timestamp Comparison for Health Failure Recency

**Description:** Two functions compare numeric Unix timestamp strings to determine whether a failure occurred more recently than a success. They share identical core logic (parse as `u64`, compare `failure > success`, fallback to string comparison) but differ slightly in arity and naming.

### Occurrences

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/ui/stations.rs` | `station_health_failure_is_current()` | 246–255 |
| 2 | `src/ui/station_details.rs` | `failure_is_after_success()` | 254–259 |

### Evidence

`src/ui/stations.rs`:
```rust
fn station_health_failure_is_current(success: Option<&str>, failure: Option<&str>) -> bool {
    match (success, failure) {
        (_, None) => false,
        (None, Some(_)) => true,
        (Some(success), Some(failure)) => match (success.parse::<u64>(), failure.parse::<u64>()) {
            (Ok(success), Ok(failure)) => failure > success,
            _ => failure > success,
        },
    }
}
```

`src/ui/station_details.rs`:
```rust
fn failure_is_after_success(success: &str, failure: &str) -> bool {
    match (success.parse::<u64>(), failure.parse::<u64>()) {
        (Ok(success), Ok(failure)) => failure > success,
        _ => failure > success,
    }
}
```

The core comparison (`parse::<u64>` then `failure > success` with string fallback) is identical. `station_health_failure_is_current` wraps the same logic with `Option<&str>` handling.

### Proposed Abstraction

- **Target module:** `src/radio/station.rs` (station health is a domain concept)
- **Signature:**
  ```rust
  impl StationHealth {
      /// Returns true when the most recent failure timestamp is newer than the most recent success.
      pub fn failure_is_more_recent(&self) -> bool
  }
  ```
- **Variation points:** None. The two-argument form becomes `StationHealth::failure_is_more_recent()` operating on its own `last_success_at` / `last_failure_at` fields.

## Pattern 4: Bitrate Formatting and Fallback Value Helpers

**Description:** Bitrate display formatting appears in two UI files with near-identical logic. Additionally, a string-fallback helper (`fallback` / `empty_fallback`) is duplicated with identical implementations.

### Occurrences — Bitrate

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/ui/stations.rs` | `bitrate_chip()` | 265–272 |
| 2 | `src/ui/station_details.rs` | `bitrate_label()` | 268–275 |

**Difference:** When `bitrate == 0`, `bitrate_chip` returns `"?k"` while `bitrate_label` returns `"Unknown"`. For non-zero values, both return `format!("{bitrate}k")`.

### Occurrences — Fallback Helper

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/ui/stations.rs` | `empty_fallback()` | 343–348 |
| 2 | `src/ui/station_details.rs` | `fallback()` | 276–282 |

**Difference:** None. Implementations are byte-for-byte identical in logic — only the function name differs.

### Evidence

`src/ui/stations.rs`:
```rust
fn empty_fallback<'a>(value: &'a str, fallback: &'a str) -> &'a str {
    if value.trim().is_empty() { fallback } else { value.trim() }
}
```

`src/ui/station_details.rs`:
```rust
fn fallback<'a>(value: &'a str, fallback: &'a str) -> &'a str {
    if value.trim().is_empty() { fallback } else { value.trim() }
}
```

### Proposed Abstraction

- **Target module:** `src/ui/mod.rs` or a new `src/ui/format.rs` utility module
- **Signatures:**
  ```rust
  /// Returns `fallback` if value is blank/whitespace-only, otherwise returns trimmed value.
  pub fn str_or<'a>(value: &'a str, fallback: &'a str) -> &'a str

  /// Formats a bitrate for display; `context` controls the zero-case label.
  pub fn format_bitrate(bitrate: u32, compact: bool) -> String
  // compact=true → "?k", compact=false → "Unknown"
  ```
- **Variation points:** The zero-bitrate label (`"?k"` vs `"Unknown"`) is the only variation; a `compact: bool` or enum parameter resolves it.

## Pattern 5: Codec Display Formatting Across Boundaries

**Description:** Station codec formatting for display exists in three different locations, each normalizing the codec string (trim → uppercase) and then presenting it differently:

1. `src/app/playback.rs` — `display_station_codec()`: Uppercases the codec for error notices; returns `"Unknown codec"` for empty.
2. `src/ui/stations.rs` — `codec_chip()`: Uppercases and appends a capability indicator (`?` or `!` suffix).
3. `src/ui/station_details.rs` — `codec_detail()`: Uses `fallback()` for empty, calls `codec_capability()`, and appends a prose description (`"· playable"`, `"· not playable yet"`).

All three share the initial normalize step (`trim` → `is_empty` check → `to_ascii_uppercase`) and two of the three also call `crate::audio::codec_capability()`.

### Occurrences

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/app/playback.rs` | `display_station_codec()` | 246–253 |
| 2 | `src/ui/stations.rs` | `codec_chip()` | 273–289 |
| 3 | `src/ui/station_details.rs` | `codec_detail()` | 173–184 |

### Evidence

`src/app/playback.rs`:
```rust
fn display_station_codec(codec: &str) -> String {
    let codec = codec.trim();
    if codec.is_empty() { "Unknown codec".to_string() } else { codec.to_ascii_uppercase() }
}
```

`src/ui/stations.rs`:
```rust
fn codec_chip(station: &crate::radio::Station) -> String {
    let codec = station.codec.trim();
    if codec.is_empty() { return "codec ?".to_string(); }
    let capability = crate::audio::codec_capability(codec);
    match capability.capability {
        Supported => codec.to_ascii_uppercase(),
        Unknown => format!("{} ?", codec.to_ascii_uppercase()),
        Unsupported => format!("{} !", codec.to_ascii_uppercase()),
    }
}
```

### Proposed Abstraction

- **Target module:** `src/radio/station.rs` or `src/audio/capability.rs` (where `codec_capability` already lives)
- **Signature:**
  ```rust
  pub enum CodecDisplayStyle { Short, Chip, Detailed }

  pub fn format_codec_display(codec: &str, style: CodecDisplayStyle) -> String
  ```
- **Variation points:** `CodecDisplayStyle` controls empty-case label and capability suffix format. The normalize step (`trim` → `to_ascii_uppercase`) becomes the shared core.

## Pattern 6: Close Hint Overlay Footer

**Description:** Two overlay modules define their own `close_hint()` function to render a dismissal hint line. The logic is identical (construct a `Line` with styled key + "closes this panel" text), differing only in which key is displayed (`" g "` + `" Esc/q "` vs. `" i "`).

### Occurrences

| # | File | Function | Lines |
|---|------|----------|-------|
| 1 | `src/ui/recent_tracks.rs` | `close_hint()` | 163–171 |
| 2 | `src/ui/station_details.rs` | `close_hint()` | 261–267 |

### Evidence

`src/ui/recent_tracks.rs`:
```rust
fn close_hint() -> Line<'static> {
    Line::from(vec![
        Span::styled(" g ", theme::cyan()),
        Span::styled("or", theme::dim()),
        Span::styled(" Esc/q ", theme::cyan()),
        Span::styled("closes this panel", theme::dim()),
    ])
}
```

`src/ui/station_details.rs`:
```rust
fn close_hint() -> Line<'static> {
    Line::from(vec![
        Span::styled(" i ", theme::cyan()),
        Span::styled("closes this panel", theme::dim()),
    ])
}
```

### Proposed Abstraction

- **Target module:** `src/ui/mod.rs` (alongside existing `render_boundary_warning`)
- **Signature:**
  ```rust
  pub fn overlay_close_hint(keys: &[&'static str]) -> Line<'static>
  ```
- **Variation points:** `keys` — the key labels to display (e.g., `["g", "Esc/q"]` or `["i"]`).
