Already addressed in Part A (decomposition). The prebuffer loop's inner `match` with nested error sends becomes:

```rust
fn fill_prebuffer(...) -> Result<Vec<u8>, PrebufferError> {
    loop {
        // Guard clauses first (early returns)
        if pre.len() >= min_bytes { return Ok(pre); }
        guard_active_or_bail(gen, &active)?;
        check_timeout_or_bail(start, timeout)?;
        
        match stream.read(&mut chunk[..read_len]) {
            Ok(0) => return Ok(pre),
            Ok(n) => { pre.extend_from_slice(&chunk[..n]); emit_progress(...); }
            Err(e) if abandoned(&e) => return Err(PrebufferError::Abandoned),
            Err(_) => return Ok(pre), // attempt with partial data
        }
    }
}
```

### B5. `fail_or_recover()` — Depth 6

- **File:** `src/audio/engine_loop_v2.rs` (lines 333–379)
- **Location:** `Ok(())` → `if let Some(url)` → state transition construction

#### Flattening Proposal

Use guard clause for the None case:

```rust
fn fail_or_recover(&mut self, error: EngineError, url: Option<String>) {
    if self.output.try_recover().is_err() {
        self.transition_to(EngineState::Failed { url, error: error.clone() });
        self.emit(AudioStatus::Error(error.to_status_string()));
        return;
    }
    
    let Some(url) = url else {
        self.transition_to(EngineState::Idle);
        self.emit(AudioStatus::Stopped);
        return;
    };
    
    // Reconnect path — flat, no nesting
    let gen = self.supervisor.next_generation();
    self.transition_to(EngineState::Connecting { generation: gen, url: url.clone() });
    self.emit(AudioStatus::Connecting);
    self.supervisor.spawn(...);
}
```

## Part C: Summary of Recommendations

### High Priority (≥100 logic lines OR nesting ≥6 in production code)

1. **`run_worker()`** — Decompose into 4 pipeline-stage functions
2. **`render_visualizer_signal()`** — Extract per-state rendering into dedicated functions
3. **`handle_event()`** — Extract per-event-variant handlers
4. **`render()` in stations.rs** — Extract genre tabs + list item builder

### Medium Priority (50–100 logic lines OR nesting 5)

5. **`render_status_bar()`** — Split status chip logic from right-section assembly
6. **`run()` in cli.rs** — Extract subcommand handlers
7. **`draw_model()`** — Extract layout-mode content renderer
8. **`update_visualizer()`** — Extract FFT sample extraction and spectrum decay
9. **`handle_command()`** — Extract per-command handlers
10. **`apply_selected_setting()`** — Extract per-row setting appliers
11. **`sleep_lines()`** — Extract status line and control hints
12. **`recent_track_lines()`** — Extract history vs session branches

### Low Priority / Acceptable (flat dispatchers, data literals)

- `fallback_stations()` — flat data literal, no refactoring needed
- `update()` in update.rs — thin action dispatcher, no nested logic
- `map_normal()` in event.rs — flat key-mapping match, readable as-is
- `build_deck_lines()` — sequential construction, no branching
- `normal_mode_footer()` — declarative span assembly
