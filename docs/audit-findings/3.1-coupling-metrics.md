# 3.1 — Import Graph & Coupling Metrics

## Methodology

Parsed all `mod`, `use`, `pub use`, `use super::`, and `crate::` statements across every `.rs` source file to build a directed import graph. Coupling is computed at the **module file** level:

- **Afferent coupling (Ca):** How many other module-files import from (depend on) this file.
- **Efferent coupling (Ce):** How many other module-files this file imports from.
- **Instability (I):** Ce / (Ca + Ce) — values near 1.0 indicate high instability (many outgoing deps, few incoming), values near 0.0 indicate high stability (many dependents, few outgoing deps).
- **Hotspot:** Ca > 3 AND Ce > 3 (both heavily imported and heavily importing).

For sub-modules (e.g., `src/app/playback.rs`), `use super::*` is treated as importing from the parent module's public interface (i.e., all sibling types re-exported by `src/app.rs`). Cross-crate dependencies (e.g., `ratatui`, `tokio`, `serde`) are excluded — only intra-crate edges count.

## Hotspot Files (Ca > 3 AND Ce > 3)

### 🔥 `src/app.rs` (+ `src/app/*`) — **The Central Hub**

| Metric | Value |
|---|---|
| Ca (afferent) | **10** — imported by: main.rs, runtime.rs, event.rs, ui/mod.rs, ui/model.rs, ui/search.rs, ui/stations.rs, ui/controls.rs, ui/header.rs, ui/settings.rs, ui/command_palette.rs, ui/sleep_timer.rs, ui/playback_doctor.rs, ui/critical.rs, ui/deck/* |
| Ce (efferent) | **7** — imports from: audio, radio, favorites, history, config, action, ui::theme, playlist_export |
| Instability | 0.41 |
| Boundary | app-state |

**Assessment:** The `app` module is the system's gravity well — nearly everything depends on it (all UI renderers consume its types) and it depends on nearly every other boundary. This is expected for a central application state module, but the **bidirectional dependency with `ui::theme`** (`app/settings.rs` → `crate::ui::theme::ThemeName`) is a layering violation (app-state importing from ui-rendering).

## Additional File-Level Hotspot Analysis

While no individual file outside `app` crosses the Ca>3 AND Ce>3 threshold at the strict file level, the following files exhibit elevated coupling:

### `ui/model.rs` — High Ca within UI boundary

- **Ca:** ~14 (all UI renderers import `UiModel` from this file)
- **Ce:** 4 (app, favorites, history, radio)
- This is the bridge between app-state and ui-rendering — expected but worth monitoring.

### `ui/stations.rs` — High Ce for a renderer

- **Ce:** 4 (app, radio, audio, text)
- For a pure rendering module, importing from audio-engine (`codec_capability`) is unusual — it should consume pre-computed data from UiModel.

### `ui/station_details.rs` — Direct audio import

- **Ce:** 2 (radio, audio)
- Same pattern as stations.rs: importing `crate::audio::codec_capability` directly.

### `ui/settings.rs` — Direct audio import

- **Ce:** 2 (app, audio)
- Imports `crate::audio::output_device_display_name` — presentational logic that could be pre-computed.

## Key Findings for Consolidation

1. **Hotspot: `src/app` module** — Ca=10, Ce=7, I=0.41. This module is the system's coupling nexus. Any change to its public types ripples to 10+ dependents. Its dependency on 7 other modules means it's sensitive to changes in nearly every other boundary.

2. **Layering violation: `app/settings.rs` → `crate::ui::theme::ThemeName`** — The app-state layer imports a type from the ui-rendering layer. The theme name enum should live in a shared/cross-cutting location or be represented as a plain string at the app-state boundary.

3. **UI renderers bypass UiModel for audio capability** — `ui/stations.rs`, `ui/station_details.rs`, and `ui/settings.rs` import directly from `crate::audio` to access `codec_capability` and `output_device_display_name`. This violates the design's stated adjacency rule that ui-rendering should access audio data only via pre-computed fields in `UiModel`.

4. **Radio module is maximally stable (I=0.0)** — It has zero outgoing dependencies to other crate modules and 8 incoming consumers. This is excellent architecture — it's a leaf dependency.

5. **Audio module is maximally stable (I=0.0)** — Same pattern as radio: zero upward dependencies, 7 consumers. Clean layering.

6. **`ui/model.rs` is the intended firewall** — All rendering modules go through it (Ca≈14), confirming the UiModel pattern is being followed — except for the 3 audio capability bypasses noted above.
