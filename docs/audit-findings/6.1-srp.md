# 6.1 Single Responsibility Principle (SRP) Violations

_Requirements: 4.1, 4.2, 4.3, 4.4_

## Summary

Evaluated the `App` struct, its sub-structs (`UiRuntimeState`, `PlaybackRuntime`, `PlaybackView`), and functions in `src/app/playback.rs` for Single Responsibility Principle violations. Each field is classified as app-state, ui-rendering, audio-engine, or infrastructure. Functions that span multiple separation boundaries are flagged.

---

## 1. `App` Struct Field Classification (`src/app.rs`)

| Field | Classification | Justification |
|-------|---------------|---------------|
| `library: Library` | app-state | User's persisted station library |
| `search: SearchState` | app-state | Current search query and results |
| `history: History` | app-state | Persisted listening history |
| `song_history: VecDeque<String>` | app-state | In-session track history |
| `undo_history: VecDeque<(Station, usize, String)>` | app-state | Undo stack for station removal |
| `ui: UiRuntimeState` | ui-rendering | Nested UI state aggregate |
| `playback: PlaybackRuntime` | audio-engine | Nested audio/playback aggregate |
| `metadata_refresh_pending: bool` | infrastructure | Network request scheduling |
| `metadata_refresh_running: bool` | infrastructure | Network request state tracking |
| `persist: PersistFlags` | infrastructure | Dirty-flag tracking for disk I/O |

**SRP Assessment:** The `App` struct has **3 responsibility boundaries** in its flat fields:
- **app-state:** 5 fields
- **ui-rendering:** 1 container (delegates to `UiRuntimeState`)
- **audio-engine:** 1 container (delegates to `PlaybackRuntime`)
- **infrastructure:** 3 fields

**Violation — SRP-001:** `metadata_refresh_pending`, `metadata_refresh_running`, and `persist` are infrastructure concerns (network scheduling, disk I/O tracking) that leak into the top-level application aggregate. These should be grouped into a dedicated infrastructure sub-struct or extracted to a separate coordination layer.

**Severity:** Low — The composition-root pattern makes some mixed responsibilities acceptable. The infrastructure fields are simple booleans that don't dominate the struct.

## 2. `UiRuntimeState` Field Classification (`src/app/ui_runtime.rs`)

| Field | Classification | Justification |
|-------|---------------|---------------|
| `nav: Navigation` | app-state | Selected station index, genre index — drives business logic decisions |
| `command_palette: CommandPaletteState` | ui-rendering | Palette filter text and selection |
| `should_quit: bool` | app-state | Application lifecycle flag |
| `notice: NoticeState` | ui-rendering | Transient user notification display |
| `input_mode: InputMode` | ui-rendering | Keyboard routing mode |
| `tick_count: u64` | ui-rendering | Animation tick counter |
| `layout_mode: LayoutMode` | ui-rendering | Panel layout configuration |
| `overlays: Overlays` | ui-rendering | Active overlay stack |
| `visualizer_mode: usize` | ui-rendering | Which visualizer variant to render |
| `visualizer_peaks: Vec<f32>` | audio-engine | FFT spectral data from audio engine |

**SRP Assessment:**
- **ui-rendering:** 6 fields
- **app-state:** 2 fields (`nav`, `should_quit`)
- **audio-engine:** 1 field (`visualizer_peaks`)

**Violation — SRP-002:** `visualizer_peaks: Vec<f32>` is raw audio spectral data produced by the audio engine's FFT pipeline and stored inside a UI state struct. This crosses the audio-engine → ui-rendering boundary.

**Proposed decomposition:**
- Extract `visualizer_peaks` to a `VisualizerSnapshot` struct or pass it via the `UiModel` builder without storing it in `UiRuntimeState`.
- The audio engine already writes to `sample_buffer: Arc<Mutex<VecDeque<f32>>>` in `PlaybackRuntime`. The FFT computation in `src/app/visualizer/` reads from that buffer and writes peaks into `ui.visualizer_peaks`. Instead, the peaks should be computed at render time or stored in a dedicated `VisualizerState` struct that lives at the boundary.
- **New module path:** `src/app/visualizer/state.rs` → `pub struct VisualizerState { pub mode: usize, pub peaks: Vec<f32> }`
- **Public interface:** `VisualizerState::update_peaks(&mut self, samples: &[f32])`, `VisualizerState::peaks(&self) -> &[f32]`

**Violation — SRP-003:** `nav: Navigation` and `should_quit: bool` are application-level state (they determine business logic flow — which station is selected, whether the app exits) but live in a struct named "UiRuntime". Navigation selection drives which station gets played; `should_quit` controls the event loop.

**Proposed decomposition:**
- Move `nav` and `should_quit` to `App` struct directly, or to a new `AppControl` sub-struct.
- `UiRuntimeState` would then contain only fields that affect rendering output.
- **Impact:** Moderate refactor — `self.ui.nav` → `self.nav` or `self.ctrl.nav` across ~15 call sites. `self.ui.should_quit` → `self.should_quit` or `self.ctrl.should_quit`.

**Severity:** Medium — The boundary bleed is real but tolerable in a single-developer TUI app. Becomes problematic if UI rendering is ever separated into its own thread or crate.

## 3. `PlaybackRuntime` Field Classification (`src/app/playback_runtime.rs`)

| Field | Classification | Justification |
|-------|---------------|---------------|
| `view: PlaybackView` | app-state | Playback state visible to UI (state, URL, track) |
| `volume: u8` | audio-engine | Current volume level sent to audio output |
| `muted: bool` | audio-engine | Mute flag sent to audio output |
| `reconnect: Reconnect` | infrastructure | Automatic reconnection scheduling with backoff |
| `diagnostics: PlaybackDiagnostics` | infrastructure | Debug/diagnostic data for playback doctor overlay |
| `sleep_timer: SleepTimer` | app-state | User-facing sleep timer feature |
| `audio: AudioEngine` | audio-engine | Handle to the audio engine command/status channels |
| `sample_buffer: Arc<Mutex<VecDeque<f32>>>` | audio-engine | Shared audio sample ring buffer for visualization |

**SRP Assessment:**
- **audio-engine:** 4 fields (`volume`, `muted`, `audio`, `sample_buffer`)
- **app-state:** 2 fields (`view`, `sleep_timer`)
- **infrastructure:** 2 fields (`reconnect`, `diagnostics`)

**Violation — SRP-004:** `PlaybackRuntime` conflates three distinct responsibilities:
1. **Audio control** — sending commands to the audio engine, managing volume/mute
2. **App-level features** — sleep timer (a user-facing feature with its own overlay and controls)
3. **Infrastructure resilience** — reconnection logic with backoff timers and diagnostic data collection

**Proposed decomposition:**

| New struct | Fields | Module path |
|-----------|--------|-------------|
| `AudioControl` | `audio`, `volume`, `muted`, `sample_buffer` | `src/app/audio_control.rs` |
| `PlaybackState` (rename `PlaybackView`) | `view` (or flatten its fields) | `src/app/playback.rs` (existing) |
| Keep `SleepTimer` | standalone (already a struct) | Move ownership to `App` directly |
| `PlaybackResilience` | `reconnect`, `diagnostics` | `src/app/playback_resilience.rs` |

**Public interfaces:**
- `AudioControl::send(&self, cmd: AudioCommand) -> bool`
- `AudioControl::output_volume_fraction(&self) -> f32`
- `PlaybackResilience::arm_reconnect(&mut self, url: String, now: Instant)`
- `PlaybackResilience::take_due(&mut self, now: Instant) -> Option<String>`

**Severity:** Medium — The sleep timer being bundled with audio engine handles is the most surprising aspect. Adding a new timer-like feature (e.g., alarm, scheduled recording) would require touching `PlaybackRuntime` which should only concern itself with audio.

## 4. `PlaybackView` Field Classification (`src/app/playback.rs`)

| Field | Classification | Justification |
|-------|---------------|---------------|
| `state: PlaybackState` | app-state | Current playback FSM state |
| `playing_url: Option<String>` | app-state | URL of the active stream |
| `current_track: Option<String>` | app-state | Currently playing track title |
| `buffer_percent: u8` | audio-engine | Buffering progress from audio engine |
| `buffer_seconds: u32` | audio-engine | Buffer fill level in seconds |
| `intentional_stop: bool` | app-state | Flag to distinguish user-stop from engine failure |

**SRP Assessment:**
- **app-state:** 4 fields
- **audio-engine:** 2 fields (`buffer_percent`, `buffer_seconds`)

**Violation — SRP-005 (minor):** `buffer_percent` and `buffer_seconds` are transient audio engine metrics that flow upward for display. They live in `PlaybackView` which is otherwise a "what's happening" snapshot for the UI.

**Assessment:** This is a pragmatic boundary — these fields are consumed solely for UI display and are updated by audio status events. They're "audio data presented to the app layer" which is the legitimate boundary of a view-model. **Minor SRP tension, not a strong violation.** No decomposition recommended unless buffering metadata grows.

## 5. Functions Mixing Playback State Transitions with Notice Formatting

### `src/app/playback.rs`

**Violation — SRP-006:** Multiple functions in `playback.rs` perform **both** playback state machine transitions (updating `PlaybackView` fields, sending `AudioCommand`s) **and** user-facing notice formatting (calling `set_info_notice`/`set_error_notice` with human-readable messages). These are two distinct responsibilities:
1. **State transition logic** — deterministic FSM updates
2. **Notice presentation** — formatting user-facing messages with display logic

| Function | State transition | Notice formatting |
|----------|-----------------|-------------------|
| `send_audio_command` (line 29) | Sets `PlaybackView` to error state, updates `diagnostics` | `set_error_notice("Audio engine is not available")` |
| `validate_station_playback_capability` (line 69) | Resets `PlaybackView`, sets `Error` state, clears URL | `set_error_notice(format!("{} is not playable yet ({})", ...))` — includes codec display formatting via `display_station_codec()` |
| `retry_stream` (line 101) | Resets buffer/track, sets `Connecting` state | `set_info_notice("Retrying stream")` |
| `export_library` (line 152) | N/A (delegates to `playlist_export`) | `set_info_notice(format!("Library exported to {}", ...))` / `set_error_notice(format!("Export failed: {err}"))` |

**Additional violations in `src/app/lifecycle.rs`:**

| Function | State transition | Notice formatting |
|----------|-----------------|-------------------|
| `handle_audio_error` (line ~200) | Resets buffer, arms reconnect, sets `Error` state | Updates `diagnostics.last_recovery` with formatted string |

**Additional violations in `src/app/reconnect.rs`:**

| Function | State transition | Notice formatting |
|----------|-----------------|-------------------|
| `drive_reconnect` (line ~56) | Sets `Connecting`/`Error` state, calls `sync_volume` | `set_info_notice(format!("Reconnecting ({n}/{max})"))` |

**Additional violations in `src/app/sleep_timer.rs`:**

| Function | State transition | Notice formatting |
|----------|-----------------|-------------------|
| `announce_sleep_timer` (line ~148) | None | `set_info_notice(format!("Sleep timer: {label}"))` / `set_info_notice("Sleep timer off")` |
| `check_sleep_timer` (line ~155) | Calls `stop_playback()` | `set_info_notice("Sleep timer ended playback")` |

**Proposed decomposition:**

1. **Separate notice formatting from state transitions** by having state transition functions return a `TransitionResult` enum:
   ```rust
   pub(super) enum TransitionOutcome {
       Ok,
       Failed { notice: NoticeKind },
       Info { notice: NoticeKind },
   }
   
   pub(super) enum NoticeKind {
       AudioUnavailable,
       UnsupportedCodec { codec: String, reason: String },
       RetryingStream,
       Reconnecting { attempt: u8, max: u8 },
       SleepTimerState { label: String, waiting: bool },
       ExportSuccess { path: PathBuf },
       ExportFailed { error: String },
   }
   ```

2. **A single `apply_notice` function** maps `NoticeKind` to formatted strings and calls `set_info_notice`/`set_error_notice`. This centralizes all notice text in one place, making i18n or message format changes a single-point edit.

3. **New module path:** `src/app/notices.rs` — contains the `NoticeKind` enum and the `App::apply_notice(&mut self, notice: NoticeKind)` method.

4. **Public interface:**
   ```rust
   // In src/app/notices.rs
   impl App {
       pub(super) fn apply_notice(&mut self, kind: NoticeKind) {
           match kind {
               NoticeKind::AudioUnavailable =>
                   self.set_error_notice("Audio engine is not available"),
               NoticeKind::UnsupportedCodec { codec, reason } =>
                   self.set_error_notice(format!("{codec} is not playable yet ({reason})")),
               // ...
           }
       }
   }
   ```

**Severity:** Medium — The current pattern works but means that testing playback state transitions requires asserting on notice text strings. Separating concerns would allow pure-logic tests on state transitions and separate tests for notice formatting.

## 6. `display_station_codec` — Presentation Logic in Playback Module

**Violation — SRP-007:** The helper function `display_station_codec()` at the bottom of `src/app/playback.rs` is pure display/formatting logic (converts a raw codec string to a user-presentable label). It exists in a module whose primary responsibility is playback state machine transitions.

**Proposed decomposition:**
- Move to `src/text.rs` (which already exists as a cross-cutting text utilities module) or to a new `src/app/display.rs` module for app-layer formatting helpers.
- Signature: `pub fn display_station_codec(codec: &str) -> String`

**Severity:** Low — Single function, minor organizational concern.

---

## 7. `export_library` — File I/O in Playback Module

**Violation — SRP-008:** `App::export_library()` in `src/app/playback.rs` performs filesystem path resolution (`export_directory()`) and delegates to `playlist_export` for disk I/O, then formats the result into a notice. This function:
1. Resolves a filesystem path (infrastructure concern)
2. Calls an I/O operation (infrastructure concern)
3. Formats success/failure notices (presentation concern)
4. Lives in a module named "playback" (state machine concern)

**Proposed decomposition:**
- Move `export_library` and `export_directory` to `src/app/library.rs` (which handles library management operations) or a new `src/app/export.rs`.
- The function already delegates I/O to `playlist_export`, which is correct. The issue is that it lives in the wrong module — it has nothing to do with playback state transitions.

**Severity:** Low — Misplaced function, not a deep architectural issue.

## Recommended Refactoring Priority

1. **SRP-004** (Medium) — Decompose `PlaybackRuntime` into `AudioControl` + move `SleepTimer` to `App`. Most impactful structural improvement; reduces coupling between unrelated features.
2. **SRP-006** (Medium) — Separate notice formatting from state transitions. Enables pure-logic testing of the playback FSM.
3. **SRP-002** (Medium) — Extract `visualizer_peaks` from `UiRuntimeState`. Clarifies the audio→UI data flow.
4. **SRP-003** (Medium) — Move `nav`/`should_quit` out of `UiRuntimeState`. Makes the naming honest.
5. **SRP-001, SRP-005, SRP-007, SRP-008** (Low) — Minor organizational improvements, worth doing as part of larger refactors but not standalone priorities.
